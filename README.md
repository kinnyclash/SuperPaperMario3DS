# spm3ds

A native New Nintendo 3DS port of Super Paper Mario, built by static recompilation.

This repository contains only original code. It does not contain Nintendo's game files, ROMs, disc images, keys or decompiled source. You supply your own legally obtained extracted files. See [docs/REQUIRED_FILES.md](docs/REQUIRED_FILES.md).

## Status

Early development. The host tooling and tests work. The New 3DS build is written but has not been compiled against devkitARM yet. See [PROGRESS.md](PROGRESS.md).

## Layout

- `spm3ds/`: host tooling in Python.
  - `dol.py`: DOL parser and loader.
  - `memory.py`: guest memory map.
  - `ppc.py`: PowerPC decoder and reference interpreter.
  - `analysis.py`: function discovery, tail-call classification, linear sweep.
  - `jumptables.py`: declared jump tables for bctr dispatch.
  - `jumpdetect.py`: automatic switch-table detection from the code (bound check plus lwzx load).
  - `recomp.py`: PowerPC-to-C recompiler and the `analyze` and `compile` CLI. Includes paired singles.
  - `diagnose.py`: shareable Markdown diagnostic report for a `main.dol` (no game bytes).
  - `hle.py`: symbol file parsing and binding of known OS function names.
  - `gx/tev.py`: GX TEV combiner reference model.
  - `gx/textures.py`: GX texture decoders (I4, I8, IA4, IA8, RGB565, RGB5A3, RGBA8, CMPR).
  - `gx/cp.py`: portable GX command processor (command stream, vertices, transform, culling).
  - `gx/raster.py`: host software rasterizer (depth, blend, texturing). `gx/png.py`: PNG writer.
  - `quant.py`: paired-single quantization rules (GQR types 4 to 7).
  - `input.py`: Wii Remote to 3DS key mapping.
- `runtime/`: C runtime shared by generated code, tests and the 3DS build.
  - `ppc_ctx.h`: guest context, memory access, FP, integer, carry and paired-single helpers.
  - `mem.c`: sparse paged guest memory (64 KiB pages committed on first touch).
  - `hle.h`, `hle.c`: OSReport, memcpy, memset and cache operations.
  - `os.c`: Wii OS compatibility layer: guest heap, timers, and sandboxed file reads.
  - `input.h`: Wii Remote to 3DS key conversion. `audio_ring.h`: PCM conversion and ring buffer.
- `tools/make_synthetic.py`: builds the synthetic demo that the 3DS app runs.
- `tools/windows/build.bat`: runs the tests and the 3DS build on Windows (untested here).
- `tools/windows/diagnose.bat`: writes a shareable diagnostic report for a `main.dol` (untested here).
- `tests/`: automated tests. Test programs are hand-encoded PowerPC, and some are checked against LLVM's assembler.
- `docs/`:
  - `WINDOWS_SETUP.md`: installing Python and devkitPro on Windows.
  - `REQUIRED_FILES.md`: which files you need from your own disc, and how to keep them private.
  - `GX_PICA_DESIGN.md`: design of the GX-to-PICA200 translation layer.
- `platform/3ds/`: New 3DS build (devkitARM and libctru). Not yet verified.
  - `source/main.c`: entry point. Runs the synthetic demo and shows PASS or FAIL.
  - `source/generated/synthetic.c`: generated by `tools/make_synthetic.py`. Do not edit by hand.
  - `source/diag_screen.c`: hardware diagnostics (press Y). UNCOMPILED on hardware.
  - `source/experimental/gx_citro3d.c`: citro3d backend. Excluded from the build. UNCOMPILED.
  - `shaders/passthrough.v.pica`: picasso shader for the experimental backend. Not assembled.
- `.github/workflows/build-3ds.yml`: CI for host tests and the 3DS build. UNTESTED.
- `docs/samples/`: PNG images rendered by the host software renderer (no game data).

## Running the tests

```
python3 -m unittest discover -s tests -t .
```

Expect `Ran 168 tests ... OK`. The equivalence tests need a host `gcc`, and the LLVM encoding test needs `llvm-mc`. Without them those tests are skipped, and the run still passes.

## Regenerating the 3DS demo source

```
python3 tools/make_synthetic.py
```

This rewrites `platform/3ds/source/generated/synthetic.c`. A test fails if the checked-in file differs from the generator output.

## Analysing a DOL (your own file)

List every instruction the project does not support yet, with addresses. Nothing is written.

```
python3 -m spm3ds.recomp analyze /path/to/your/main.dol
python3 -m spm3ds.recomp analyze /path/to/your/main.dol --symbols syms.txt --jump-tables tables.txt
```

The symbol file has one `ADDRESS NAME` pair per line (hexadecimal address). Names that match a known OS function are bound to host implementations. Other names are listed as unimplemented.

The jump-table file has one declaration per line, for a `bctr` whose table is known:

```
JUMPTABLE <bctr address> <table address> <entry count>
```

## Compiling a DOL (your own file)

```
python3 -m spm3ds.recomp compile /path/to/your/main.dol out/game.c --symbols syms.txt --jump-tables tables.txt
```

The output includes `runtime/ppc_ctx.h` and `runtime/hle.h`. Compile it with `runtime/hle.c` and `runtime/os.c`. Generated code is derived from Nintendo's program. Keep it on your own machine.

Unsupported instructions on reachable code stop the compile and report the address.
